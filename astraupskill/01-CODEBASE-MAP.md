# Codebase map

`.nettrello` is a small ASP.NET Core board API with a Vite client. The API starts in `src/NetTrello.Api/Program.cs`, registers one singleton `InMemoryBoardRepository`, a clock, and scoped `BoardService`, then maps `/health` and `/api/boards`. The endpoint file stays thin: it binds request records, reads `X-Board-Version`, invokes the service, and returns an HTTP result. `ExceptionHandlingMiddleware` turns `DomainException` into a problem response containing status, detail, code, and trace id.

The domain owns invariants. `Board` owns ordered columns and members; `BoardColumn` owns ordered cards and capacity; `Card` owns title, nullable description, priority, assignment, due date, labels, position, and timestamps. `BoardService.MutateAsync` asks the repository for a clone while holding the expected-version check inside the repository update callback. The callback either returns an updated aggregate or throws. `InMemoryBoardRepository` protects updates with `SemaphoreSlim`, clones before callbacks, stores a clone after success, and returns clones on reads.

The improvement follows this call graph: PATCH route -> `UpdateCardAsync` -> `UpdateCardRequest.ResolveAgainst(currentCard)` -> `Board.UpdateCard` -> `Card.Update`; move route -> `Board.MoveCard` -> target lookup, position/capacity validation, then removal and insertion. The DTO uses nonnullable `JsonElement`: `JsonValueKind.Undefined` means omitted, while `JsonValueKind.Null` means explicit JSON null. That distinction is the central wire contract. The repository clone boundary remains useful and is tested separately from domain validation. Read [the xUnit suite](../tests/NetTrello.Tests) before reading the full UI; `BoardFixture.cs` shows the arrangement and `CardPatchTests.cs` shows the contract one case at a time.


The client reinforces the API contract rather than changing it. `boardClient.updateCard` sends JSON and the board version header; `CardEditor` sends a complete object, including null for an unassigned card and no due date. The server therefore supports both legacy complete updates and newer partial callers. `BoardMapper` returns positions and updated timestamps, which makes an ordering regression visible to a client. When studying the code, read the mapper after the domain methods so response fields are not mistaken for persistence fields.


A useful reading technique is to mark every method that accepts `DateTimeOffset now`. Those methods are deterministic under `FixedClock`, and each successful aggregate operation should touch the board exactly once. The repository never exposes its dictionary, so tests must observe through `GetAsync`. This architecture is intentionally compact: it demonstrates boundaries without claiming that a concurrent dictionary is a durable store.
